widocznosc.ai · Dystrybucja treści · Instrukcja

Do uruchomienia automatu potrzebne są dwie wartości: ID dedykowanej strony widocznosc.ai i token, który nie wygasa

Automat jest gotowy w repozytorium (ten sam mechanizm, który od kwietnia publikuje wpisy BusManiak.pl). Codziennie od poniedziałku do piątku o 11:00 wybiera losowy wpis z bloga widocznosc.ai, generuje opis i publikuje link na stronie. Blokuje go tylko brak dostępu do strony na Facebooku – ten dokument opisuje, co i w jakiej kolejności pozyskać.

Co trzeba mieć na końcu

  1. Dedykowana strona widocznosc.ai na Facebooku, podpięta do portfolio firmowego ICEA (Meta Business Portfolio), z rolą administratora dla osoby, która zakłada dostępy.
  2. Aplikacja w Meta for Developers typu „Firma”, przypisana do tego samego portfolio. Może zostać w trybie deweloperskim – publikacja na własnej stronie nie wymaga App Review.
  3. Użytkownik systemowy w Business Portfolio z dostępem do strony i wygenerowanym tokenem bez daty wygaśnięcia. To jedyny wariant tokena, który nie wymaga odnawiania co 60 dni.
  4. Dwie wartości wpisane do GitHub Secrets repozytorium zaplecze: FB_WIDOCZNOSC_PAGE_ID oraz FB_WIDOCZNOSC_ACCESS_TOKEN. Klucz do modelu językowego (OPENROUTER_KEY) już tam jest, wspólny z BusManiakiem.

Weryfikacja tokena przed przekazaniem

Dwa wywołania z terminala potwierdzają, że token jest właściwy, widzi stronę i nie wygasa. Wykonuje je osoba, która ma token w ręku – wynik nie zawiera nic wrażliwego i można go wkleić do wątku.

Warunek: w odpowiedzi debug_token pole expires_at ma być 0, a type – USER z is_valid: true. Wartość inna niż 0 oznacza token tymczasowy z Graph API Explorer – automat przestanie działać po 60 dniach.
Uwaga: tokena nie wysyłamy mailem ani na czacie. Trafia bezpośrednio do GitHub Secrets; jeśli musi przejść przez ręce dwóch osób, użyć wiadomości znikającej i po wpisaniu do sekretów wygenerować nowy (stary unieważnić w panelu użytkownika systemowego).

Plan

1

Założyć stronę widocznosc.ai

Nazwa, nazwa użytkownika, kategoria, awatar (znak widocznosc.ai), okładka, opis z linkiem do https://widocznosc.ai/. Strona może na razie zostać nieopublikowana publicznie – automat i tak potrzebuje jej ID.

Mateuszprzed krokiem 2
2

Podpiąć stronę do portfolio ICEA

Business Settings → Konta → Strony → Dodaj. Osoba dodająca musi być administratorem zarówno strony, jak i portfolio.

administrator portfolio ICEApo kroku 1
3

Utworzyć aplikację typu „Firma”

W tym samym portfolio. Zapisać ID aplikacji i klucz tajny (do weryfikacji tokena). Tryb deweloperski zostaje.

Mateuszpo kroku 2
4

Użytkownik systemowy z dostępem do strony i aplikacji

Dodać użytkownika, przypisać stronę z pełną kontrolą i aplikację, wygenerować token bez wygaśnięcia z trzema uprawnieniami. Skopiować token od razu – ekran nie pokaże go ponownie.

administrator portfolio ICEApo kroku 3
5

Zweryfikować token i wpisać sekrety

Dwa wywołania z sekcji wyżej, potem GitHub → repozytorium zaplecze → Settings → Secrets and variables → Actions → New repository secret: FB_WIDOCZNOSC_PAGE_ID, FB_WIDOCZNOSC_ACCESS_TOKEN.

Mateuszpo kroku 4
6

Pierwszy przejazd ręczny

GitHub → Actions → „Facebook Auto-Poster (widocznosc.ai)” → Run workflow. Sprawdzić post na stronie i wpis w pipeline/fb-poster/posted-widocznosc.json. Od następnego dnia roboczego automat rusza sam o 11:00.

Mateuszpo kroku 5

Do rozstrzygnięcia w kolejnym etapie

  • Newsy w puli automatu – dziś publikuje tylko wpisy bloga (50). Codzienne newsy z widocznosc.ai/news/ można dołożyć osobnym harmonogramem, jeśli strona ma mieć więcej niż jeden post dziennie.
  • Częstotliwość – ustawione pon–pt 11:00. Zmiana to jedna linia w .github/workflows/fb-poster-widocznosc.yml.
  • Instagram i LinkedIn – token użytkownika systemowego z tego samego portfolio obsłuży też konto Instagram firmowe (wymaga dodatkowo instagram_content_publish); LinkedIn to osobne API i osobna zgoda.
